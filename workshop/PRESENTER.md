# Deliver the workshop

Use 10 minutes to introduce the boundary: shared project, isolated execution,
explicit access. Show the whole factory as a destination, then tell attendees
that today's hands-on checkpoint is their own kit and repeatable environment.
The team is a continuation they can follow at their own pace.

Start at [the attendee map](README.md). Work through steps 1–4 in sequence.
Judge progress by what attendees can observe:

- The agent writes a file they can see, but cannot read the neighbouring host file.
- Docker runs inside SBX, and the host browser reaches its app through a port.
- A pasted task becomes a visible commit; an MCP call retrieves the same task.
- Their own kit installs a command; recreating the sandbox picks up their edit.
- ACR installs guidance, and the review cites a concrete rule and piece of code.
- The environment file recreates the workspace, kits, port and task connection.

Protect time for authoring the kit. The app is there to make execution and shared
files tangible. Do not spend the session polishing its interface or waiting on a
long implementation. Step 2 includes a completed warm-up checkpoint; use it if
needed, then inspect the resulting code against the task.

Keep the task/MCP comparison short: one pasted task, one actual retrieval, one
comparison. A tool list alone does not demonstrate task access. The kit exercise
should include the attendee's own greeting change and recreation; that is the
moment the reusable definition becomes concrete.

When time runs short, finish the current observation and point to the next heading.
At the end, have attendees locate their `factory/` files and the continuation
link. A working configuration they understand is a useful stopping point.

For a team preview, show the role briefs, one handoff and one human question.
Explain that `crew` runs inside SBX and all roles can share one Claude account and
model. Provider comparison and host orchestration answer later needs.

Before delivery, rehearse the guide on the target SBX release and host platforms.
Check model login, first image download, Windows dependency storage, MCP host
command approval, kit creation and environment cleanup. The maintainer review
record distinguishes completed checks from outstanding platform rehearsals.
